# Contributing

Short guide to contribute:

1. Open an issue

- Describe the problem, steps to reproduce and include logs if possible (PM2 log, browser console).
- Remove API keys and image URLs (they carry access tokens) first. Security problems go through [SECURITY.md](SECURITY.md), not through a
  public issue.

2. Develop locally

- `cd modules/MMM-Photoprism2`
- `git submodule update --init --recursive` (only needed if you cloned without `--recurse-submodules`)
- `npm ci`
- `node --run lint` — Biome check
- `node --run test` — unit tests (`node:test`)
- `node --run check` — MagicMirror module checker (needs the devcontainer)

Run at least `node --run lint` and `node --run test` before opening a PR.

`lib/mmm-shared` is a git submodule. Changes to it belong in
[HeikoGr/mmm-shared](https://github.com/HeikoGr/mmm-shared); `node --run shared:update` pulls a new
version into this module.

**Development Container:** see [docs/DEVCONTAINER.md](docs/DEVCONTAINER.md).

3. Commit

PRs are squash-merged, so the **PR title** becomes the commit on `develop` and follows
[Conventional Commits](https://www.conventionalcommits.org/). CI checks it with
`scripts/check-commit-msg.js`; the messages of the individual commits in your branch are free-form.
A breaking change is marked with `!` in the title.

```
<type>(<optional scope>): <subject>
```

Types: `feat`, `fix`, `perf`, `refactor`, `docs`, `test`, `build`, `ci`, `chore`, `revert`.
Scopes and how to pick the type are listed in [.github/commit-instructions.md](.github/commit-instructions.md).

- **The changelog.** `CHANGELOG.md` and the version number are generated by release-please from these
  messages.
- **The version bump.** `fix` → patch, `feat` → minor, `!` → major. Do not edit `version` in
  `package.json` by hand.

CI also runs `scripts/check-commit-scope.js`, which rejects a `chore`/`docs`/`test`/`build`/`ci`/`style`
PR title when the PR changes runtime source under `lib/`, `translations/`, `node_helper.js`,
`MMM-Photoprism2.js` or `MMM-Photoprism2.css`. Pure formatting and comment-only changes
pass. For a deliberate exception, add `[allow-scope-mismatch]` to the PR title.

4. Create a PR

- Open the PR against `develop` (not `main`) with testing steps. CI runs lint, tests and the PR
  title checks.

5. Releases

Releases are prepared on `develop`: release-please keeps a `chore(develop): release x.y.z` PR up to
date. Merging it bumps the version and writes the changelog entry on `develop`. A PR to `main`
(merge commit) is then opened for exactly that release commit and merges itself once its checks
pass; the merge tags the release and creates the GitHub release.

Dependencies: Dependabot opens grouped PRs against `develop` (minor and patch, new releases wait
3 days). Updates of GitHub Actions and devDependencies merge themselves once CI passes; runtime
dependencies run on the mirror next to the user's credentials and wait for a review. Actions are
pinned to a commit SHA with the version as a comment; Dependabot keeps both up to date.

6. Style

- Use Biome. Run `node --run lint:fix` to auto-fix style issues.
